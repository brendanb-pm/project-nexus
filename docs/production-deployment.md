# Production deployment and live acceptance (NX-8.13)

This is an operator checklist, not evidence that Nexus has been deployed. Record the environment, change ticket, approvers, timestamps, and sanitized evidence in the NX-8.13 and NX-7.1A delivery records. Do not put credentials, tokens, cookies, test identities, or database URLs in those records or logs. The local Docker setup and CI database are not production infrastructure.

## Authority and environment gate

Before provisioning or changing an external system, the integration/release owner must name the authorized deployment operator and identity operator, approve the target environment and any cost, and identify a rollback owner. Record the HTTPS hostname, hosting account/project, DNS and TLS owner, approved deployment mechanism, immutable application revision, and maintenance window. No domain, hosting service, identity client, or production database is created by this repository.

Use a private, isolated PostgreSQL database and a restricted application principal. Record encryption-at-rest coverage for primary storage, replicas, and backups; retention; a recent restorable backup; and the operator and location for a restore drill. Prove the restore in an isolated target before production cutover. Never run the demo reset/seed command against an acceptance or production database. Take and verify a backup before applying migrations, run `npm run db:check`, then run `npm run db:migrate` exactly once against the approved target. Run it a second time to verify no pending work. Do not use `db:generate` or `drizzle-kit push` for deployment. If migration or smoke checks fail, stop traffic, preserve evidence, and use the approved backup/restore or forward-fix plan; do not improvise a destructive down migration.

Store `DATABASE_URL`, `BETTER_AUTH_SECRET`, and `OIDC_CLIENT_SECRET` in the approved server-side secret store with restricted access and a documented rotation owner. Set `NEXT_PUBLIC_APP_URL` to the exact HTTPS origin. Set `OIDC_ISSUER`, `OIDC_DISCOVERY_URL`, and `OIDC_CLIENT_ID` to the approved provider registration. Register exactly `${NEXT_PUBLIC_APP_URL}/api/auth/callback/nexus-oidc` as callback and `${NEXT_PUBLIC_APP_URL}/sign-in` as post-logout return. Confirm discovery/JWKS reachability and issuer equality with the identity operator. Reject example values and do not enable `NEXUS_DEV_AUTH` in deployment. See [authentication](authentication.md) for the NX-7.1A live checklist.

## Application and operations acceptance

Deploy an immutable reviewed revision through the approved protected process. Record the revision and verify TLS certificate/hostname, HTTPS redirect, application availability, database connectivity, migration version, and an authenticated protected-route smoke test. Never expose a diagnostic endpoint containing configuration, credentials, session data, or database details. Configure access/error logs with secret and report-content redaction, a health/availability monitor, alert recipient, and a tested incident escalation route. The deployment owner must record the observation window and alert test; repository CI is not evidence of deployed monitoring.

Schedule `NEXUS_REPORTING_DRAFT_EXPIRY_JOB=true npm run db:expire:reporting-drafts` in an approved server-side scheduler. It processes at most 1,000 expired payloads per invocation. Choose an interval that satisfies the 30-day draft deletion policy at measured backlog volume; alert on nonzero exit and on backlog that exceeds one run's capacity. Confirm the job uses only the approved database and that its output contains counts, not draft content. See [reporting domain](reporting-domain.md) for expiry authority and privacy constraints.

With an authorized real provider and test membership, execute the live NX-7.1A checklist: login; exact redirect and validated callback; immutable issuer/subject binding; DB-backed session; correct organization, membership, role, and protected access; logout and subsequent denial; expiry/revocation where safely observable; and authorized negative paths. Record sanitized expected/observed results, test time, deployment revision, and provider configuration reference. Development personas, mock OIDC, and CI are not substitutes.

## Launch decision

The release owner records GO only when live identity, database protection and restore, expiry scheduling, monitoring, and required independent security review/integration of client publication are evidenced. PR #52 fixture sequencing is a separate decision and must not be bypassed. Missing environment, provider, test identity, independent review, or restore evidence means NO-GO, with the exact owner and next action recorded. Keep NX-8.13 and NX-7.1A blocked until their acceptance evidence exists.
